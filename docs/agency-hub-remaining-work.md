## 核心代理闭环判断（本轮优先级）

核心闭环定义为：客户归属/禁用 → 网关按原始模型名取有效销售政策 → 请求预扣 paid/nonpaid/debt → 上游成功后结算并生成不可变账单 → Outbox 投递到 Hub → 佣金/报表投影 → 模型退款或充值拒付按原来源回滚。

当前判断：**主路径已具备并有本地及隔离三库专项通过证据，但还不是可无条件上线的完整闭环。** 正常充值、预扣、结算、佣金投影、Hub 报表和普通模型累计退款有既有通过证据；已完成 allocation 级债务身份和退款抵扣其他债务，历史 pooled debt 歧义会安全拒绝，不再将聚合债务作为未实现项重复报告。当前仍需处理：

1. **组件级支付拒付尚未完成**：缺少组件撤回、交叉水位和佣金补偿完整合同；当前 v2 拒付事务整体安全拒绝，生产自动 v2 保持关闭。
2. **异步完整生命周期仍有缺口**：通用 Task 的预扣→首次结算/取消、供应商账单初始终态及已 finalized 累计修正已实现；Midjourney 独立链和全部供应商边界/历史任务恢复仍需补齐。
3. **对账与上线门槛仍未完成**：历史日结明确失败而非错误认证；真实内部 mTLS 与命令事务已有本地通过证据，最小数据库权限、旧用户最终绑定鉴权、最终镜像和生产恢复仍需验收。

因此可以继续完善**正常代理请求的上线准备**，但不能向领导报告“支付退款/拒付所有顺序都已闭环”。W01.02 已关闭；仍须完成 W01.01 的组件拒付、W01.03/04 的实际调用链验收以及 W08.01/W08.03 的命令通道和最小权限验证，并取得最终集成验收结果，才可评估生产开关。
