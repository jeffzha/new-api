# 腾讯 ADP 智能体应用从零上架操作手册

本手册按实际界面顺序说明如何把一个新的腾讯 ADP 智能体应用，从腾讯控制台准备开始，一直到普通用户能在智能体商店中看到、启动并完成一次对话。新版主路径统一在 **智能体商店 → 上架应用** 完成；管理员不再需要先去客户页创建 Application，也不需要分别执行“启用 Customer App、验证部署、启用执行、发布”四次操作。

本文使用以下完整示例：

| 项目 | 示例值 |
|---|---|
| 应用名称 | `高考志愿无忧` |
| 腾讯 ADP AppId | `2048342527164967296` |
| Region | `ap-guangzhou` |
| SpaceId | `default_space` |
| 客户代码 | `NEXUS-INTERNAL` |
| 客户名称 | `REACH NEXUS` |
| new-api 用户 ID | `1` |

AppKey 属于敏感信息，本文只写为 `<真实 AppKey>`，不要把真实值写入文档、截图、聊天、日志或工单。

## 1. 第一步：在腾讯 ADP 控制台确认应用可用

1. 登录腾讯 ADP 控制台。
2. 打开准备上架的 Application，本例为 **高考志愿无忧**。
3. 确认该应用已经发布，不能只处于编辑或草稿状态。
4. 在应用详情中复制 AppId，本例是：

   ```text
   2048342527164967296
   ```

5. 在该 Application 的应用接入配置中取得完整 AppKey。AppKey 必须与上述 AppId 属于同一个 Application。
6. 记录应用所在 Region，本例为 `ap-guangzhou`。
7. 记录 SpaceId，本例为 `default_space`。
8. 判断应用类型。普通智能体、Multi-Agent、Workflow 和静态 Claw 不填写模板 Agent ID；只有动态 Claw 才记录并填写模板 Agent ID。

准备结果如下：

| 内容 | 示例 | 获取位置 |
|---|---|---|
| AppId | `2048342527164967296` | 腾讯 ADP 应用详情 |
| AppKey | `<真实 AppKey>` | 腾讯 ADP 应用接入配置；只在表单输入一次 |
| Region | `ap-guangzhou` | 腾讯控制台地域 |
| SpaceId | `default_space` | 腾讯 ADP 空间信息 |
| 模板 Agent ID | 动态 Claw 才填写 | 腾讯 ADP 应用/Agent 配置 |
| 平台凭据配置 | `nexus-internal-primary` | 管理端“凭据配置”；必须是 platform scope、active、环境匹配 |

## 2. 第二步：确认平台级腾讯凭据已经存在

上架表单中的 **平台凭据** 不是 AppKey。它是服务端调用腾讯管理 API 时使用的腾讯云 AK/SK 配置。正常情况下只需由技术管理员预先配置一次，后续普通超级管理员上架不同应用时直接选择配置名称。

1. 以超级管理员进入 **智能工作台管理 → 凭据配置**。
2. 查找状态为 `active`、作用域为 `platform`、供应商环境为 `china_tencent_adp` 的配置，例如 `nexus-internal-primary`。
3. 若已经存在，记录它的显示名称，继续下一步；无需查看或重新填写 SecretId、SecretKey。
4. 若不存在，需要技术管理员先把 AK/SK 安全注入服务器环境，再在此页创建只保存 `env://WORKBENCH_PROVIDER_...` 引用的配置。不要在浏览器中填写 AK/SK 明文。

平台凭据必须有权读取目标 Space 和 Application。界面只显示凭据配置名称，不显示 SecretId、SecretKey、引用、指纹或任何密钥内容。

## 3. 第三步：准备至少一个可使用 Workbench 的客户

即使上架时选择“所有符合条件的客户”，系统仍会检查客户、成员和套餐。第一次测试建议使用以下客户：

1. 进入 **客户 → 新建客户**。
2. 填写：

   | 字段 | 示例 |
   |---|---|
   | 客户代码 | `NEXUS-INTERNAL` |
   | 客户名称 | `REACH NEXUS` |
   | 计费用户 ID | `1` |

3. 创建后打开该客户详情。
4. 在 **成员 → 添加成员** 中填写 new-api 用户 ID `1`，角色首次测试可选择管理员角色。
5. 确认该客户状态为 `active`，成员状态有效。
6. 若还没有 Workbench 套餐版本，先进入 **套餐 → 创建套餐**。示例：套餐代码 `workbench-standard`、名称 `Workbench 标准版`、月价按实际业务填写；能力至少包含 `chat`。
7. 回到客户详情，在 **套餐周期 → 创建套餐周期** 中选择上述套餐，设置有效起止时间。
8. 在 **确认付款** 中选择该周期并填写内部付款凭证编号，例如 `manual-20260812-nexus-internal`。
9. 确认套餐周期同时满足“当前有效”和“已付款”。否则用户即使被选择为目标客户，也看不到或无法启动应用。

本步骤只准备客户的使用资格，不需要在客户页创建或启用腾讯 Application。

## 4. 第四步：进入上架向导

1. 以 new-api 超级管理员登录。
2. 打开 **智能工作台管理**。
3. 如页面要求近期验证，使用密码、Passkey 或已配置的二次认证完成验证。
4. 左侧进入 **智能体商店**。
5. 点击右上角 **上架应用**。

打开弹窗后，向下找到第二个区块 **腾讯 ADP 应用配置**。`App ID` 和 `AppKey` 就填写在这个区块中，不是在客户页、凭据配置页或商店展示信息区填写。

## 5. 第五步：填写商店展示信息

进入弹窗后，先填写 **商店展示信息**：

| 字段 | 本例填写 | 说明 |
|---|---|---|
| 固定标识 Slug | `gaokao-zhiyuan-wuyou` | 只能使用小写字母、数字和连字符；创建后不修改 |
| 显示名称 | `高考志愿无忧` | 用户在商店中看到的名称 |
| 简介 | `面向高考考生和家长的志愿填报辅助智能体。` | 用于列表卡片 |
| 详细说明 | `结合成绩、地区、选科和专业偏好辅助整理院校与专业选择。结果仅供信息参考，请以官方招生政策为准。` | 用于详情页 |
| 头像地址 | 留空或填写 HTTPS 图片地址 | 不要填写本地路径或 HTTP 地址 |
| 分类 | `教育` | 用于筛选 |
| 标签 | `高考, 志愿填报, 升学规划` | 使用英文逗号分隔 |
| 排序值 | `20` | 数字越小越靠前；相同排序值再按应用 ID 排序 |
| 精选应用 | 首轮不勾选 | 验证稳定后再设置 |

## 6. 第六步：填写 AppId、AppKey 和腾讯 ADP 配置

在 **智能体商店 → 上架应用 → 腾讯 ADP 应用配置** 中按下列顺序填写：

1. **供应商环境**选择 `china_tencent_adp`。
2. **Region**填写腾讯控制台中该 Application 所在地域，例如 `ap-guangzhou`。
3. **Space ID**填写该 Application 所属空间，例如 `default_space`。
4. **App ID**输入腾讯 ADP Application 的 AppId。本例完整填写：

   ```text
   2048342527164967296
   ```

   不要填写商品 Slug、AgentId、SpaceId、new-api 用户 ID 或渠道 ID。AppId 一般是一串数字，但应按腾讯控制台原样复制，不要自行转换或补空格。

5. **AppKey**输入框中粘贴与上述 AppId 属于同一个腾讯 Application 的完整 AppKey，例如：

   ```text
   <从腾讯 ADP“应用接入配置”复制的完整 AppKey>
   ```

   AppKey 不等于腾讯云 SecretId/SecretKey，也不等于 new-api API Key。不要在 AppKey 前添加 `Bearer `，不要加引号、换行或前后空格。

6. **平台凭据**选择已有的 platform scope 凭据配置。这里选择的是服务端调用腾讯管理 API 使用的 AK/SK 配置名称；它和上一步的 Application AppKey 是两种不同凭据。
7. 动态 Claw Application 才填写 **模板 Agent ID**；其他模式留空。
8. 完成其余字段后点击 **验证配置**。

对应关系如下：

| 界面字段 | 本例填写 | 不要误填成 |
|---|---|---|
| App ID | `2048342527164967296` | AgentId、渠道 ID、客户 ID |
| AppKey | 该 AppId 自己的完整 AppKey | SecretKey、new-api Key、`Bearer ...` |
| 平台凭据 | 选择 platform scope 配置名称 | AppKey |
| 模板 Agent ID | 仅动态 Claw 填写 | AppId |

点击 **验证配置** 后，AppKey 输入框会立即清空，这是安全设计，不代表未提交。后端只保存加密密文；页面、API、日志和操作手册都不会回显 AppKey。若验证失败，请重新从腾讯控制台复制完整 AppKey再填写，因为平台不会保存或回显上次输入供管理员修改。

## 7. 第七步：选择允许使用该应用的客户

在 **客户使用范围** 中二选一：

- **所有符合条件的客户**：当前及未来所有 active、成员有效且有已付款 Workbench 套餐的客户都可以看到和启动应用。
- **仅指定客户**：只允许勾选的客户使用。本例如果仍处于测试阶段，选择此项并勾选 `REACH NEXUS (NEXUS-INTERNAL)`。

“所有客户”不是匿名公开，也不会绕过登录、成员和套餐检查。多个客户共用同一个腾讯 AppId 时，对话、任务、历史、文件和用户身份仍按客户及用户隔离。

## 8. 第八步：选择能力并填写限制

第一次上架建议只启用已经验收的能力：

1. `chat`：勾选。
2. `files`：只有完成文件上传、扫描、下载和权限隔离验收后才勾选。
3. `web_search`、`tools`、`connectors`、`oauth`、`scheduled_tasks`、`sandbox`：未完成相应验收前不要勾选。页面可能默认勾选 `files`，首轮仅聊天测试时应主动取消。
4. 限制使用以下保守示例，后续再按套餐调整：

| 限制 | 示例 |
|---|---:|
| customer_concurrency | `10` |
| user_concurrency | `1` |
| max_runtime_seconds | `900` |
| max_reasoning_rounds | `20` |
| max_output_tokens | `8192` |
| web_search_per_turn | `0` |
| max_file_bytes | `0` |

## 9. 第九步：点击“验证配置”

1. 逐项复核前面填写的 Slug、AppId、Region、SpaceId、客户范围和能力。
2. 点击 **验证配置**。
3. 页面会把 AppKey 安全提交给服务端并立即清空输入框。输入框变空是正常现象，不表示 AppKey 丢失。
4. 等待验证预览。预览必须显示验证结果为 `verified`。
5. 核对腾讯返回的应用名称确实为 **高考志愿无忧**，并核对 AppMode、runtime profile 和腾讯发布状态。
6. 如果验证失败，根据错误修正表单；AppKey 不会回显，需要重新从腾讯控制台复制后再次填写。

AppMode 与运行方式应符合：

| AppMode | runtime profile | 模板 Agent ID |
|---:|---|---|
| 1 | `standard_v2` | 留空 |
| 2 | `multi_agent_v2` | 留空 |
| 3 | `workflow_v2` | 留空 |
| 4 静态 Claw | `claw_static_v2` | 留空 |
| 4 动态 Claw | `claw_dynamic_v2` | 必填 |

验证失败时，平台会清理这次未发布草稿并撤销刚写入的 AppKey 密文引用；修正后可使用相同 Slug 和 AppId 重新验证。

## 10. 第十步：点击“确认并上架”

只有验证结果为 `verified` 时，按钮才会变成 **确认并上架**。

1. 最后核对验证预览。
2. 点击 **确认并上架**。
3. 服务端会在一次事务中激活运行配置、固化 AuthEpoch、启用执行、发布目录版本并写入审计。
4. 成功后关闭弹窗，应用列表中应出现 **高考志愿无忧**。
5. 状态应为：目录应用 `published`、运行配置 `active`、执行 `enabled`。

这里不需要再到客户页启用 Application，也不需要再点击第二次“启用”或“发布”。如果任何一步失败，发布会整体回滚，不会留下半启用状态。

## 11. 第十一步：使用普通用户完成端到端验证

1. 退出超级管理员账号，或使用无管理员权限的独立浏览器会话登录 new-api 用户 ID `1`。
2. 打开 `https://gateway.nexus-reach.com/agent-store`。如果使用公网 IP 访问，应使用系统实际 HTTPS 地址，不要忽略证书错误。
3. 搜索 **高考志愿无忧**。
4. 打开详情，核对名称、简介和详细说明。
5. 点击 **启动**。启动链接有效期为 60 秒且只能使用一次；重复打开同一链接会失败，这是正常安全行为。
6. 进入智能工作台后发送：

   ```text
   我是广东物理类考生，想了解计算机相关专业。请先告诉我还需要提供哪些信息。
   ```

7. 确认收到腾讯 ADP 应用的正常回复。
8. 新建第二个无授权用户或无套餐客户做反向验证：其商店中不应看到该应用，或启动时应被拒绝。
9. 确认不同用户之间看不到彼此的对话、任务、文件和历史。

完成以上九项，才算该智能体应用已从“腾讯控制台配置”走通到“客户实际使用”。

## 13. 验证和发布原理

点击 **验证配置**。平台会使用服务端保存的腾讯凭据调用官方接口，并显示安全预览：验证结果、腾讯 AppMode、平台 runtime profile、腾讯发布状态和腾讯应用名称。

| AppMode | runtime profile | 模板 Agent ID |
|---:|---|---|
| 1 | `standard_v2` | 留空 |
| 2 | `multi_agent_v2` | 留空 |
| 3 | `workflow_v2` | 留空 |
| 4 静态 Claw | `claw_static_v2` | 留空 |
| 4 动态 Claw | `claw_dynamic_v2` | 必填 |

验证失败时，平台会清理本次未发布草稿并撤销刚写入的 AppKey 密文引用；修改表单后可以直接重试，不会被相同 Slug 或 AppId 的旧草稿阻塞。

### 13.1 确认并上架

确认预览与腾讯控制台一致后，点击 **确认并上架**。这是唯一的发布确认按钮，服务端一次完成：

1. 激活运行配置；
2. 固化最新 AuthEpoch；
3. 启用 deployment 执行；
4. 发布目录版本；
5. 写入审计和缓存失效事件。

成功后页面应直接显示：目录应用 `published`、运行配置 `active`、执行 `enabled`。不需要再点击第二个“启用”或“发布”；任一步失败都会整体回滚。

## 14. 上架后的修改、下架与删除

- **修改展示信息**：在智能体商店管理页打开相应商品的编辑操作，修改名称、简介、说明、头像、分类、标签、排序或精选状态，然后按页面提示保存并重新发布目录版本。
- **修改 AppId、AppKey、Region、SpaceId、模板 Agent 或平台凭据**：这些属于运行配置变更，必须重新验证；不能把旧验证结果用于新配置。
- **暂时停止新用户使用**：执行下架或禁用。下架主要移除目录入口；禁用还会撤销新的启动授权。填写清楚操作原因。
- **永久删除**：只有尚未产生需保留的审计、账务或运行数据且状态机允许时才能删除；生产上优先使用禁用或归档。界面不提供删除时，不要直接操作数据库。
- **重新上架**：修正配置并重新完成验证和发布，不要复用已经过期的预期行版本。

## 15. 客户侧验证清单

1. 确认测试客户为 `active`。
2. 确认测试用户是该客户的有效成员。
3. 确认客户有当前有效且已经确认付款的 Workbench 套餐周期。
4. 使用普通客户账号打开 `/agent-store`。
5. 搜索 **高考志愿无忧**，打开详情并点击 **启动**。
6. 发送测试消息：`我是广东物理类考生，想了解计算机相关专业。请先告诉我还需要提供哪些信息。`
7. 检查会话、任务和历史只对当前客户和用户可见。

“所有客户”不会绕过客户、成员或套餐检查；任何一项失效，应用都会从目录消失或启动被拒绝。

## 16. 常见问题

| 现象 | 检查方法 |
|---|---|
| 没有可选平台凭据 | 先创建并激活 platform scope、环境匹配的腾讯凭据配置 |
| AppId 找不到 | 核对环境、Region、SpaceId、AppId |
| AppKey 无效 | 从该 Application 的接入配置重新取得 AppKey |
| 应用未发布 | 先在腾讯 ADP 发布，再回平台验证 |
| 动态 Claw 验证失败 | 填写正确模板 Agent ID |
| 上架后客户看不到 | 检查客户状态、成员关系、已付款套餐周期和客户使用范围 |
| 重复打开启动链接失败 | 启动票据 60 秒有效且只能使用一次，属于正常安全行为 |
| 验证后仍显示 draft | 刷新页面确认最新状态；验证成功后还必须点击同一弹窗中的“确认并上架” |
| 提示配置在验证后发生变化 | 重新打开上架流程，以当前配置重新验证；不要手填旧的预期行版本 |
| AppKey 输入框验证后为空 | 正常的只写安全设计；服务端保存加密密文，前端不回显 |
