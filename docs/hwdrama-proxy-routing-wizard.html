Hwdrama Proxy Routing

配置向导与动态路由方案

本文记录素材接口透传服务的配置模型、wizard 生成配置的方式、运行时如何从客户请求匹配 action， 以及如何精确路由到对应上游供应商。

Nginx 固定客户入口 Action 字典集中定义 Route 按 key/model/action 匹配 配置成功后自动 reload

核心公式

请求进入 proxy 后，先由客户侧 method/path 反查 action，再用稳定 ID 精确命中 route。

action_key =
  lookup(method + path)

route =
  api_key_id + model + action_key

设计边界

Nginx 只负责把固定客户入口转发到 hwdrama-proxy，不表达上游差异。
Actions 字典 定义客户侧 endpoint 和默认上游 endpoint，避免每条 route 重复录入 downstream。
Routes 定义哪个 API Key、模型、动作应该转给哪个上游，以及必要的上游 path override。
兼容默认路由 可用 all_api_keys: true 保持“任意有效 key 都能透传”的旧行为。

推荐配置结构

配置文件建议放在 /opt/new-api/hwdrama-proxy-routes.yml。 密钥只通过环境变量引用，不进入 YAML。 

version: 1

actions:
  seedance_open_create_asset:
    downstream_method: POST
    downstream_path: /api/v3/open/CreateAsset
    default_upstream_method: POST
    default_upstream_path: /api/v3/open/CreateAsset

  seedance_open_get_asset:
    downstream_method: POST
    downstream_path: /api/v3/open/GetAsset
    default_upstream_method: POST
    default_upstream_path: /api/v3/open/GetAsset

routes:
  - name: default-hwdrama-compatible
    all_api_keys: true
    channel_id: 1
    models:
      - "*"
    upstream_base_url: https://ai.hwdrama.com
    upstream_api_key_env: HWD_HWDRAMA_API_KEY
    asset_namespace_id: hwdrama-default
    enabled_actions:
      - seedance_open_create_asset
      - seedance_open_get_asset

  - name: wetoken-seedance-oversea
    api_key_ids: [7]
    channel_id: 3
    models:
      - doubao-seedance-2-0-fast-filter-off
    upstream_base_url: https://asset.wetoken.ai
    upstream_api_key_env: HWD_WETOKEN_API_KEY
    asset_namespace_id: byteplus-oversea-main
    enabled_actions:
      - seedance_open_create_asset
      - seedance_open_get_asset

带 Override 的例子

如果某个上游的真实路径不同，只覆盖上游 method/path。客户侧接口仍然保持不变，不需要修改 Nginx。 

version: 1

actions:
  seedance_open_create_asset:
    downstream_method: POST
    downstream_path: /api/v3/open/CreateAsset
    default_upstream_method: POST
    default_upstream_path: /api/v3/open/CreateAsset

  seedance_open_get_asset:
    downstream_method: POST
    downstream_path: /api/v3/open/GetAsset
    default_upstream_method: POST
    default_upstream_path: /api/v3/open/GetAsset

routes:
  - name: supplier-x-seedance-oversea
    api_key_ids:
      - 11
    channel_id: 8
    models:
      - doubao-seedance-2-0-fast-filter-off
      - doubao-seedance-2-0-filter-off
    upstream_base_url: https://supplier-x.example.com
    upstream_api_key_env: HWD_SUPPLIER_X_API_KEY
    asset_namespace_id: supplier-x-oversea
    enabled_actions:
      - seedance_open_create_asset
      - seedance_open_get_asset
    upstream_action_overrides:
      seedance_open_create_asset:
        upstream_method: POST
        upstream_path: /v1/assets/create
      seedance_open_get_asset:
        upstream_method: POST
        upstream_path: /v1/assets/query

flowchart TD
    A["管理员运行 wizard"] --> B["选择 API Key、Channel、Models、Actions"]
    B --> C["wizard 查询 new-api 数据库"]
    C --> C1["tokens.id / token name / group"]
    C --> C2["channels.id / channel name / base_url / models"]
    C1 --> D["生成 routes 配置"]
    C2 --> D
    D --> E["写入临时配置文件"]
    E --> F["validate 配置"]
    F -->|失败| F1["拒绝写入，显示错误"]
    F -->|成功| G["原子替换 hwdrama-proxy-routes.yml"]
    G --> H["wizard 调用本机 reload"]
    H --> I["hwdrama-proxy 重新加载配置"]
    I --> J["构建内存路由表"]
    J --> J1["action 索引: downstream_method + downstream_path -> action_key"]
    J --> J2["route 索引: api_key_id + model + action_key -> route"]
    J --> J3["校验无重复、无歧义"]

请求路由与透传流程

flowchart TD
    A["客户请求 llm.ai.nexus-reach.com"] --> B["Nginx 固定拦截素材接口"]
    B --> C["转发到 hwdrama-proxy"]
    C --> D["根据 method + path 查 action"]
    D -->|找不到| D1["404: action not found"]
    D -->|method 不允许| D2["405: method not allowed"]
    D -->|命中| E["得到 action_key"]
    E --> F["读取 Authorization"]
    F -->|缺失或格式错误| F1["401: missing api key"]
    F --> G["归一化 sk-xxx"]
    G --> H["查 new-api tokens 表"]
    H -->|不存在或软删除| H1["401: invalid api key"]
    H -->|存在| I["得到 api_key_id"]
    I --> J["从请求中读取 model"]
    J -->|缺失且 route 需要 model| J1["400/404: model required or no route"]
    J --> K["用 api_key_id + model + action_key 匹配 route"]
    K -->|无匹配| K1["404: no upstream route"]
    K -->|多个匹配| K2["500: ambiguous route, 配置错误"]
    K -->|唯一命中| L["得到 route"]
    L --> M["决定上游地址"]
    M --> M1["upstream_base_url"]
    M --> M2["action 默认 upstream_path"]
    M --> M3["route 的 upstream_action_overrides 可覆盖 path/method"]
    M1 --> N["构造上游请求"]
    M2 --> N
    M3 --> N
    N --> O["覆盖 Authorization 为上游 API Key"]
    O --> P["保留业务 Header、Query、Body"]
    P --> Q["请求上游供应商"]
    Q --> R["透传上游状态码、响应头、响应体"]
    R --> S["返回客户"]

Wizard 功能规划

建议命令

/hwdrama-proxy config wizard
/hwdrama-proxy config validate
/hwdrama-proxy config reload
/hwdrama-proxy config action add
/hwdrama-proxy config action list
/hwdrama-proxy config route clone
/hwdrama-proxy config list-tokens
/hwdrama-proxy config list-channels

交互步骤

  1. 选择或新增 action，客户侧 endpoint 只在 action 字典中录入一次。
  2. 从数据库选择 API Key，wizard 自动写入 tokens.id。
  3. 从数据库选择渠道，默认带出 channel_id 和 base_url。
  4. 从渠道模型列表中选择模型，必要时允许 *。
  5. 填写上游 key 的环境变量名和 asset_namespace_id。
  6. 只有上游路径不一致时才填写 override。
  7. 预览 diff，校验成功后原子写入并自动 reload。

校验规则

规则 目的
downstream_method + downstream_path 只能对应一个 action 保证 Nginx 转发来的请求能唯一反查 action。
api_key_id + model + action_key 只能命中一个 route 避免同一个请求不知道该转发到哪个上游。
api_key_ids 必须存在且未软删除 配置使用稳定 ID，不依赖可改名的 token name。
channel_id 必须存在 保留与 new-api 渠道配置的对应关系，方便审计和排障。
upstream_path 只能是 path，不能是完整 URL 避免绕过 upstream_base_url。
密钥只允许通过 upstream_api_key_env 引用 避免真实上游密钥进入配置文件、仓库或日志。

热加载策略

wizard 写入新配置后，调用只监听本机的 reload 接口，例如 POST http://127.0.0.1:3001/-/reload。 proxy 校验新配置成功后原子替换内存路由表；失败时继续使用旧配置。
注意： 已在处理中的请求继续使用旧路由，新请求使用新路由。新增客户侧 downstream 入口时仍需要同步 Nginx； 仅修改上游路径、key、模型、渠道、namespace 时不需要改 Nginx。

最终效果

少录入 客户侧 endpoint 只在 actions 字典录一次，route 只引用 action。
可扩展 不同上游路径用 override 表达，不改客户接口。
可运维 wizard 自动查库、生成、校验、写入、reload，减少手工配置错误。
